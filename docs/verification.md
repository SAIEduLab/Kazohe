- **手順の内容**: 8012−7566の不足・隣の位からの交換・0をまたぐ判断（E10）、通分・分子の演算・約分・元の式への部分置換（E11）、図の先出し・部分積の実際の加数・整数で作業する小数の筆算と元の式への復元・仮の商と盤面の一致（E12）を、理由を省いた負例も含め検査します。

## Actionsと証跡

Actionsはmath、3エンジンのbrowser、visual、aggregateに分けます。各ジョブと集約は、対象repository・checkout SHA・head SHA・HTML SHA-256・run/attempt、およびsuiteのPASS/FAIL/NOT_RUNを短いsummaryに出力します。失敗IDとreports内の出力名から、同じrunのログ・artifactを確認できます。summary自体は合格判定を置き換えません。

- 未出力、重複、不一致、失敗、別commit・別runのレポートは集約できません。欠落はNOT_RUN、不一致や偽PASSはFAILです。失敗理由はaggregate.jsonに残ります。
- PRの合成マージSHAを検証のcheckout commitとして記録し、PR head SHAは別に保持します。各ジョブは `scripts/artifact.mjs --verify-head` でcheckoutとheadのHTMLを照合します。visualは比較基点と祖先確認のため全履歴を保持し、ほかはdepth 1です。
- 自動集約に成功したHTMLのみ候補artifactとして出力します。正式リリースは別の監査です。画像差分は承認や基点の更新には使用しません。

## 目視と実機

スクリーンショットの作成は目視合格ではありません。筆算の位、借り越し、小数点、部分積、商の0、入力欄の欠け、説明の折返し、学年に合う言葉、選択内容と支援の分かりやすさを実画像で確認し、Public内で画像の対象となったcommit、Actions run ID、確認者、環境と画像を `tests/evidence/visual-review.json` に記録します。記録のcommitがこのリポジトリの履歴にあり、HTMLハッシュが一致することも正式リリース時に確認します。未確認項目は `NOT_RUN` です。

ブラウザ自動化やタッチ設定は物理端末での試験とは別です。PC・タブレット・スマホで実機証跡がなければTC-B15は `NOT_RUN` です。通常の `npm run audit:release` は目視・実機が未実施なら非0で終了します。
